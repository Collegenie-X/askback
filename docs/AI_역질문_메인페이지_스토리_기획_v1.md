# 메인 페이지 스토리 기획 v1 — "한 화면에서 루프가 한 바퀴 돈다"

## 0. 한 줄 정의

메인 페이지의 첫 영역은 **설명하는 자리가 아니라, 루프가 실제로 한 바퀴 도는 것을 보여주는 자리**다.
기능 나열(무엇이 있다) → 한 사례의 흐름(어떻게 흘러간다)로 바꾼다.

---

## 1. 필요성 — 왜 지금 이 구조인가

| 지금 | 문제 | 바뀐 뒤 |
|---|---|---|
| 기능을 문단으로 설명 | 읽어야 이해됨 | 보면 이해됨 |
| 역질문·화이트보드·리포트가 따로 놓임 | 관계가 안 보임 | 하나의 사례로 이어짐 |
| "AI가 되묻는다"는 말만 있음 | 증거가 없음 | 되묻는 장면이 눈앞에 있음 |

핵심 전제: **이 서비스의 차별점은 기능이 아니라 순서다.** 순서는 목록으로 못 보여주고, 한 사례가 흘러가는 걸로만 보여진다.

---

## 2. 더 나은 방안 제안 — "스토리 스트립(Story Strip)"

제안한 대로 전체 루프를 한 영역에 넣되, **정적 다이어그램이 아니라 한 사례가 재생되는 스트립**으로.

```
[ 상단 1영역 : 스토리 스트립 ]
 ┌─────────────────────────────────────────────┐
 │  ① 던진다      ② 답 + 되묻기   ③ 화이트보드  │
 │  "동네 빵집을    "…그럼 단골과   "순서도로     │
 │   앱으로"        뜨내기 중       그려보면?"    │
 │                  누구를 위한?"                 │
 │                                               │
 │  ④ 리포트(10턴)  ⑤ .md 로 남는다             │
 └─────────────────────────────────────────────┘
        ● ○ ○ ○ ○   ← 자동 재생 + 클릭 이동
```

- 한 사례(예: 빵집 앱)를 **처음부터 끝까지** 한 번에 보여준다.
- 사용자는 "이 앱에서 나한테 무슨 일이 일어나는가"를 5칸으로 예습한다.
- 스트립의 마지막 칸이 곧 CTA: "내 아이템으로 이 루프 돌려보기".

### 왜 이게 원안보다 나은가
- 루프를 "설명"하면 4개의 기능이 되고, "재생"하면 1개의 경험이 된다.
- 5칸이 그대로 **제품의 정보구조**이기도 하다 → 아래 세부 섹션이 이 5칸의 확대판이 된다.

---

## 3. 전제 구조 — 페이지 전체 뼈대

```
메인
├─ A. 스토리 스트립        ← 전체 루프 (이번 단계에서 먼저 만든다)
│    └ 마지막 칸 = 시작 버튼
├─ B. ①의 확대 — 어떤 아이템이든 받는다 (예시 칩들)
├─ C. ②의 확대 — 되묻기가 만드는 차이 (되묻기 있음/없음 비교)
├─ D. ③의 확대 — 화이트보드 테스트 (순서도·핵심·차별점 3칸)
├─ E. ④의 확대 — 리포트 실물 (8칸 형식 그대로)
├─ F. ⑤의 확대 — .md 로 주고받기
└─ G. 다시 시작 CTA
```
A만 먼저 완성하고, B~G는 A의 각 칸을 눌렀을 때 내려가는 목적지로 붙인다.

---

## 4. 알고리즘 — 스트립이 도는 규칙

```
입력: 시연용 사례 1개 (샘플 대화 .md)
상태: step ∈ {1..5}

반복:
  step 카드를 화면에 세운다
  대사 1~2줄을 타이핑처럼 흘린다
  4초 대기 (또는 사용자가 점/화살표 클릭)
  step ← step + 1
  step > 5 이면:
      마지막 칸을 CTA 상태로 고정하고 정지   ← 무한 루프 금지
사용자가 한 번이라도 조작하면 자동 재생은 끈다
스크롤로 A영역을 벗어나면 정지 (다시 들어오면 그 자리부터)
```

접근성/모션: `prefers-reduced-motion` 이면 5칸을 **동시에 펼쳐 놓는다**(정적 스트립).

## 5. 마인드맵

```
                      ┌ 무엇이든 받는다 (진입 장벽 0)
        ① 던진다 ─────┤
                      └ 예시 칩 (고르면 바로 시작)

                      ┌ 답은 준다 (막히지 않는다)
        ② 되묻는다 ───┤
   루프 ─             └ 한 번 더 넓힌다 (다른 방안 / 열린 방향)

                      ┌ 순서도
        ③ 화이트보드 ─┼ 핵심
                      └ 차별점        ← 2답 1문 규칙의 그 질문

        ④ 리포트 ─── 10턴, 8칸, 프로젝트별 N번째

        ⑤ .md ─────── 남는다 · 주고받는다 · 다시 이어서 한다
```

## 6. 데이터 — .md 하나로 관리

스트립 내용은 코드에 박지 않고 `docs/` 의 시연 대본 .md 하나에서 읽는다.

```md
## step 1 | 던진다
> 동네 빵집을 앱으로 만들고 싶어요.

## step 2 | 답하고 되묻는다
답: 주문·재고·단골 3개로 쪼개집니다.
되묻기: 그럼 단골과 뜨내기 중 누구의 하루를 먼저 바꾸실 건가요?
...
```
→ 대본만 고치면 메인 페이지의 이야기가 바뀐다. 기획자가 직접 손댈 수 있는 지점.
