# 메인 페이지 스토리 기획 v2 — "요약을 먼저 정의하고, 나머지를 그 아래 건다"

v1의 문제: 전체 흐름(5칸)을 맨 위에 세웠지만, 그 아래 STAGE 01~11은 **여전히 따로 흘러간다**.
요약과 본문이 이어지지 않으면 요약은 장식이 된다.

## 1. 바뀌는 것 — 요약이 "목차"가 된다

```
[ 전체 요약 프로세스 ]   ← 이 한 영역이 페이지 전체의 지도
        │
   ┌────┼────┬────┐
   ▼    ▼    ▼    ▼      각 칸에 "본문 어디로 가면 되는지" 번호가 박힌다
 STAGE  STAGE STAGE ...   본문 STAGE는 자기가 몇 번 칸 소속인지 머리에 달고 있다
```

## 2. 3막 구조 — 11개 STAGE를 3덩이로 접는다

| 막 | 질문 | STAGE | 요약 영역에서의 역할 |
|---|---|---|---|
| **왜** | 왜 이게 필요한가 | 01 몰래→인정 · 02 문제 · 03 빈칸 · 04 누구에게 · 05 원칙 | 5칸 **위**의 전제 한 줄 |
| **어떻게** | 무슨 일이 일어나는가 | 06 사용법 · 07 되묻기 · 08 다섯 형식 · 09 남는 것 | **5칸 본체** |
| **그래서** | 무엇이 달라지는가 | 10 같은 3주 · 11 비교 | 5칸 **아래**의 결과 한 줄 |

## 3. 5칸 ↔ 본문 STAGE 연결표

| 칸 | 이름 | 본문 |
|---|---|---|
| ① | 던진다 | STAGE 06 사용법 · STAGE 08 다섯 형식 |
| ② | 답하고 되묻는다 | STAGE 07 되묻기 |
| ③ | 화이트보드 테스트 | STAGE 07 되묻기 (2답 1문) |
| ④ | 리포트 | STAGE 09 남는 것 |
| ⑤ | .md로 남는다 | STAGE 09 남는 것 |

→ 칸을 누르면 해당 STAGE로 내려간다. 반대로 STAGE 머리에는 `① 던진다` 뱃지가 붙는다.
→ 상단 메뉴의 현재 위치도 STAGE 이름이 아니라 **몇 번 칸에 있는지**로 읽힌다.

## 4. 요약 영역 최종 형태

```
        ── 왜 ──  "몰래 쓰는 AI를, 설명할 수 있는 AI로."        (01~05로)

 ① 던진다 → ② 답하고 되묻는다 → ③ 화이트보드 → ④ 리포트 → ⑤ .md
            ╰──── 여기가 핵심 (크게) ────╯
            각 칸 하단: "자세히 → STAGE 07"

      ── 그래서 ──  "같은 3주가, 설명할 수 있는 3주가 된다."     (10~11로)
```

## 5. 알고리즘 — 지도와 본문의 동기화

```
스크롤 시:
  현재 보이는 STAGE를 찾는다
  그 STAGE가 속한 칸(①~⑤ 또는 왜/그래서)을 구한다
  상단 메뉴에 그 칸 이름을 띄운다
칸을 클릭하면:
  연결표의 첫 STAGE로 스크롤
```

## 6. 이 구조의 이점

- 요약이 **한 번 읽고 버리는 것**이 아니라, 끝까지 따라다니는 좌표가 된다.
- 11개를 3막으로 접어 "길다"는 느낌이 사라진다.
- ②③이 크다는 사실이 요약에서 한 번, 본문 뱃지에서 또 한 번 반복된다.
