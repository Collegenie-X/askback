# 다섯 칸 — AskBack의 뼈대 (원본)

이 문서가 **원본**입니다. `/about`의 전체 흐름 영역과 앱 온보딩 첫 화면은 여기서 읽어 갑니다.
표를 고치고 아래 명령을 돌리면 두 화면이 같이 바뀝니다.

```bash
node scripts/build-flow.mjs
```

- `핵심` 열이 `★` 인 칸만 크게 그려지고 금색으로 표시됩니다.
- `본문` 열은 `/about`에서 "자세히 →"가 데려갈 STAGE id 입니다.
- 화면마다 말투가 다른 **설명 문장은 각 화면의 JSON**에 남습니다. 여기서 정하는 것은 **순서 · 이름 · 색 · 핵심 표시 · 목적지**입니다.

| 번호 | 아이콘 | 이름(소개) | 이름(앱) | 색 | 핵심 | 본문 | 본문 이름 |
|---|---|---|---|---|---|---|---|
| 01 | 💬 | 던진다 | 던진다 | #a78bfa |  | how | STAGE 06 사용법 |
| 02 | 🙋 | 답하고 되묻는다 | 답+되묻기 | #fbbf24 | ★ | askback | STAGE 07 되묻기 |
| 03 | 🧑‍🏫 | 화이트보드 테스트 | 화이트보드 | #f472b6 | ★ | askback | STAGE 07 되묻기 |
| 04 | 📊 | 리포트 | 리포트 | #67e8f9 |  | output | STAGE 09 남는 것 |
| 05 | 📄 | .md로 남는다 | .md로 남기 | #86efac |  | output | STAGE 09 남는 것 |

## 왜 원본이 하나여야 하는가

이 제품의 차별점은 기능이 아니라 **순서**입니다. 순서가 두 군데에 따로 적혀 있으면 언젠가 어긋나고,
어긋나는 순간 "소개에서 본 것"과 "앱에서 겪는 것"이 다른 제품이 됩니다.
그래서 순서만큼은 .md 한 장에서만 정합니다 — 이 서비스가 사용자에게 시키는 일을, 제품 자신에게도 적용합니다.
